## はじめに

株式会社ピーアールアイで開発してきた自社プロダクト **「マニュアルさん」** を公開しました。

https://manualsan.com/

マニュアルさんは、製品マニュアルや取扱説明書、手順書といった社内文書を取り込むと、ふだん使っている言葉のままの質問に **出典付き** で答えるAIナレッジ検索SaaSです。「このマニュアルのどこかに書いてあるはずだけど、探すのに時間がかかる」「詳しい人に聞かないと分からない」——そんな日常の困りごとを解決するために作りました。

この記事では、マニュアルさんで何ができるのか、そしてどういう仕組みで動いているのかを紹介します。

## マニュアルさんができること

1. **出典付きのAI検索** — ふだんの言葉で質問すると、取り込んだマニュアルを横断して回答します。回答には必ず出典（文書名・該当箇所）が付きます
2. **長いマニュアルの取り込み** — 数百ページのPDFやWordも、FAQや記事に書き直すことなくそのまま取り込めます。取り込んだ時点でAIが索引化し、検索できる状態にします
3. **Google Drive・Box からの取り込み** — 手元のファイルだけでなく、Google Drive・Box 上のファイルを選択して取り込めます
4. **回答ドラフトの作成** — お客様からの技術的な質問（メールなど）を貼り付けると、AIがマニュアルから探した該当箇所をもとに返信文の下書きを作ります。メール作成サポートのようなイメージです
5. **改訂差分の通知** — マニュアルの新版を取り込むと、旧版との変更点を検出してチームに知らせます

主なターゲットは、製品ラインが多く、カタログやマニュアルが数十〜数百冊あるメーカーの営業組織です。ただし営業に限らず、オペレーター・新人研修など「文書に答えがあるのに、探せない」場面全般で使えるように設計しています。

## 3つのこだわり — まずは一言ずつで

マニュアルさんには設計上のこだわりが3つあります。

1. **出典のない回答は出さない** — AIの答えには必ず引用が付きます。答えが本当に正しいか、誰でも元の文書で確かめられます
2. **検索は2つのモードから選べる** — 急ぎの確認にはすぐに答えるモード、大事な調べものには時間をかけて見落としを減らすモード。場面に応じて使い分けられます
3. **ファイルを「あずけない」** — 取り込んだファイルは自社で管理するサーバーに保管し、外部のファイル共有サービスには預けません

ここから先は、それぞれがどういう仕組みで実現されているかの技術的な説明です。専門的な内容なので、読み飛ばして「まとめ」に進んでいただいても大丈夫です。

## こだわり①: 出典のない回答は出さない

AIによる社内ナレッジ検索で最大の問題は、**もっともらしい誤答（ハルシネーション）** です。回答が正しいかどうかを確かめるために結局原文を探すのでは、本末転倒です。

そのため、マニュアルさんでは以下の点を意識しました。

- 探索エンジンは **原文の抽出のみ** を行い、要約・言い換えを挟まずに該当箇所を特定する
- 回答には **必ず出典**（どの文書の・どの箇所か）を付ける。出典が示せない回答は出さない
- LLMには文書全体ではなく、検索で絞り込んだ **関連箇所のみ** を渡し、無関係な情報からの誤生成を抑える

「AIの回答をそのまま信じる」のではなく、「AIが見つけてきた根拠を人が確認できる」ことを、プロダクトの前提にしています。

## こだわり②: 検索の2つのモード

検索には「速く答えてほしい日」と「見落としを減らして調べたい日」があります。マニュアルさんはこの2つを別モードとして提供します。

|                | ⚡ クイックモード                            | 🔍 精密モード                              |
| -------------- | -------------------------------------------- | ------------------------------------------ |
| 手法           | ベクトル検索を中心とした従来型のナレッジ検索 | 候補を言葉の一致と意味の近さの両方で採点し直して絞り込む |
| 答えるまで     | すぐに答える                                 | 少し時間をかけて調べる                     |
| 向いている場面 | 日常のちょっとした確認・即答したい商談中     | 重要案件・見落としを減らしたい技術照会     |

一般的なRAGは、質問と意味が近い断片を上位から数件取り出して答えます。型番やエラーコードのように、意味の近さでは探しにくい言葉を含む質問では、答えの箇所が候補の奥に埋もれて取りこぼしが起きます。マニュアルさんの精密モードは、ベクトル検索で集めた候補を **言葉の一致と意味の近さの両方で採点し直し**、該当箇所を絞り込んでから回答します。

速度と網羅性はトレードオフです。そのトレードオフをシステム側が勝手に決めるのではなく、**ユーザーが場面に応じて選べる** ようにしたのが、このプロダクトの設計判断です。

## こだわり③: ファイルを「あずけない」保管

企業のマニュアルには、機密性の高い製品仕様やノウハウが含まれます。多くの企業では、社内規程で汎用LLMサービスへの機密文書アップロードが禁止されています。

マニュアルさんでは、取り込まれたファイルを **自社管理のAWSサーバーの暗号化ディスクにテナント別に保管** します。外部のファイル共有SaaSやオブジェクトストレージにファイルを預けることはありません。索引化・回答生成の過程で必要な範囲のテキストをAI処理に使いますが、**ファイルそのものを外部に保管・送信することはない** 構成です。

## 技術スタック

| レイヤー             | 技術                                                                        |
| -------------------- | --------------------------------------------------------------------------- |
| フロントエンド / BFF | Next.js（App Router）+ Server Actions                                       |
| LLM呼び出し          | AI SDK（プロバイダー非依存）                                                |
| 文書処理パイプライン | BullMQ + Redis（アップロード → 抽出 → 分割 → Embedding → 索引化）           |
| データストア         | PostgreSQL + pgvector（Row Level Security によるテナント分離）              |
| 探索エンジン         | FastAPI（Python）による独自NLPマイクロサービス（テキスト抽出・分割・候補の採点） |

探索エンジンは別プロダクトで本番運用してきたものをマイクロサービスとして共有利用しており、ゼロから作ったものではなく **実運用で鍛えられたエンジン** です。
