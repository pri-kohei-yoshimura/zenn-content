## はじめに

AS/400 は IBM が 1988 年に発表したサーバーの製品名で、IBM i はその系統の OS の今の名前（2008 年初めから）です。IBM i は IBM Power Systems 向けの OS として提供されており、現場で「AS/400」と呼ばれているシステムは、多くの場合この IBM i で動いています。

IBM i を初めて引き継ぐ技術者は、次の 3 点を最初に押さえておくと理解が早くなります。

1. TIMI（Technology Independent Machine Interface）
2. オブジェクトを単位とする設計
3. OS に組み込まれたデータベース Db2 for i

以下は IBM の公式の解説をもとにしています。

## 名前の対応表

時期によって機械と OS の名前が変わっているため、資料や会話に出てくる名前を次の表で読み替えます。

| 名前 | 種類 | 補足 |
|---|---|---|
| AS/400（Application System/400） | 機械 | 1988 年に発表 |
| OS/400 | OS | AS/400 の OS。System/36・System/38 の多くのアプリケーションと互換 |
| iSeries・System i | 機械 | OS/400 の流れをくむ OS が中核 |
| IBM Power Systems | 機械 | 2007 年に発表。AIX で動く RS/6000 系と機械の共通化が進んだ結果 |
| IBM i | OS | 2008 年初めに付いた今の名前 |
| Db2 for i | データベース | OS の一部として組み込まれている |

出典は、IBM の歴史のページ「The AS/400」と、IBM Developer の解説「Getting started with IBM i」です（末尾の参考を参照）。

## TIMI：機械の世代が変わってもプログラムを作り直さない仕組み

IBM i のアプリケーションは、TIMI という機械から独立した層に向けてコンパイルされます。IBM の解説では、この設計により、アプリケーションの書き直し・変更・再コンパイルを行わずに、下の機械を変更できるとされています。

長年にわたって作られ、コンパイルされてきたプログラムが、新しい世代の IBM i でも動いているのはこのためです。一方で、ソースが手元になくても動き続けるため、保管されているソースと稼働中のプログラムが一致しているかは、引き継ぎの時点で別に確認する必要があります。

## オブジェクトを単位とする設計

IBM i とその前身の OS は、オブジェクトを単位とする設計です。プログラムやファイルなど、システム上のものはそれぞれがオブジェクトとして扱われます。

Linux や Windows のように「すべてはファイル」と考えて調べ始めると、構成を把握しにくくなります。引き継ぎでは、どの種類のオブジェクトがいくつあるかを一覧にするところから始めると、全体の規模を見積もりやすくなります。

## Db2 for i：OS に組み込まれたデータベース

IBM i のデータベース Db2 for i は OS の一部です。IBM の解説では、OS に同梱されているのではなく OS の一部だと説明されています。

外部のシステムとつなぐときは、データベースの表の構成と、どのプログラムがどの表を更新しているかを先に把握しておきます。

## 使える言語とオープンソース

IBM i では、CL・RPG・C/C++・Java・PHP が使え、これらの言語を使うための仕組みは標準で含まれています。オープンソースの Apache Web Server も IBM i に含まれています。

| 言語 | 現場での主な用途 |
|---|---|
| RPG | 伝票・帳票・集計などの業務処理 |
| CL | ジョブの制御・処理の順番の定義 |
| Java・PHP | Web の画面・ほかのシステムとの連携 |

既存の RPG の業務処理を残したまま、Java や PHP で Web の画面や API を追加する構成も選べます。全面的に作り直す前に、この構成で足りるかを比較しておくと、移行の範囲を小さくできます。

## 引き継ぎで確認する項目

IBM i のシステムを引き継ぐときに、最初に確認する項目は次のとおりです。

1. 機械の機種と IBM i のバージョン、ハードウェアの保守契約の期限
2. オブジェクトの一覧（プログラム・ファイルなどの種類と数）
3. ソースの保管場所と、稼働中のプログラムとの一致
4. Db2 for i の表の構成と、表を更新しているプログラム
5. 外部との連携（ファイルの受け渡し・Web・ほかのサーバー）

依頼する側が事前に整理しておく項目は、会社のサイトのナレッジ「[AS/400（IBM i）の保守を外部に依頼する前に整理しておくこと](https://pr-i.co.jp/knowledge/as400-maintenance-outsourcing/)」にまとめています。

## よくある質問

### AS/400 と IBM i は何が違いますか

AS/400 は 1988 年に発表された機械の製品名で、IBM i は 2008 年初めから使われている OS の名前です。同じ系統の製品で、今は IBM Power Systems 向けの OS として IBM i が提供されています。

### 古い AS/400 のプログラムは、新しい機械でも動きますか

IBM i のアプリケーションは TIMI に向けてコンパイルされるため、IBM の解説では、再コンパイルせずに下の機械を変更できるとされています。実際の移行では、ソースと稼働中のプログラムの一致や、外部との連携を事前に確認します。

### IBM i で Java や PHP は使えますか

使えます。IBM の解説では、CL・RPG・C/C++・Java・PHP を使うための仕組みが標準で含まれているとされています。Apache Web Server も含まれています。

### Db2 for i は別に購入・導入する必要がありますか

IBM の解説では、Db2 for i は OS の一部とされています。別の製品として導入するデータベースとは扱いが異なります。

## まとめ

IBM i は AS/400 の系統を引き継ぐ OS で、TIMI・オブジェクト単位の設計・組み込みの Db2 for i を押さえると、古いシステムの構成を読み解きやすくなります。引き継ぎでは、ソースと稼働中のプログラムの一致を最初に確認しておくと、後の作業の見積もりが安定します。
